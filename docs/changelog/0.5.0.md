# 0.5.0 — 2026-07-01

Resume ingress safety before Stage 1, plus frontend flow and display polish. Backend is **0.5.0**.

### Backend

- **Input safety (`input_safety.py`):** regex and phrase blocklist, then `meta-llama/Llama-Prompt-Guard-2-22M` (chunked HF text-classification); shared **400** message on block.
- **PII deletion:** Presidio analyze + remove (email, phone, person, location, US SSN); optional contact-header line strip; delete-not-replace to avoid token inflation.
- **Pipeline:** `prepare_resume()` runs at the start of `run_pipeline` and on `POST /v1/stages/1`.
- **Config:** `[llm.input_guard]`, `[input_safety]`, `schemas.input_guard`.
- **Prompt hardening:** Stage 1 and Stage 3 synthesis prompts treat user content as untrusted.
- **Progress copy:** Stage 2 user-facing messages no longer mention O\*NET (e.g. “Accessing career metadata database…”).
- **Deps:** `presidio-analyzer`, `presidio-anonymizer`, `spacy`, `en_core_web_sm`.

### Frontend

- **Optional criteria step:** after resume + first **Go →**, users set location/remote/salary/industries on a dedicated screen; pipeline runs from the second **Go →** (resume + constraints in one request).
- **Input panel:** frosted-glass `.input-panel` (more transparent in light and dark themes).
- **Profile display:** “Domains” relabeled **Industry experience** (including confidence-map labels); section divider above industry/strengths block.
- **Matches display:** hide O\*NET codes; show **high / medium / low** badges derived from similarity score (≥ 0.70 / ≥ 0.65 / below).
- **Errors:** injection and validation failures on the criteria step return the user there with the existing API error message.

### Fixtures and tests

- Malicious resume + injection request JSON; input-guard golden fixtures and schema.
- Mocked unit/API/stream tests for blocklist rejection, guard wiring, and Presidio path.
- Frontend tests for criteria navigation and updated match/profile labels.
