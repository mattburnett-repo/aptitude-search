# 0.3.0 — 2026-06-27

O\*NET integration release. Frontend and backend are both **0.3.0**. This version adds an offline O\*NET Postgres corpus, vector occupation matching in Stage 2, and UI/CI coverage for the new pipeline output.

### Product

- **Three-stage pipeline (unchanged flow):** resume → aptitude profile (Stage 1) → O\*NET match + role family plan (Stage 2) → profile-driven job search → `verified_matches` (Stage 3).
- **O\*NET-grounded role families:** Stage 2 embeds the aptitude profile, retrieves top-K O\*NET occupations from Postgres, and injects those matches into the role-family LLM prompt before building `search_terms` and `work_modes`.
- **Visible occupation matches:** `POST /v1/pipeline` and `POST /v1/stages/2` return `occupation_matches` (`onetsoc_code`, title, similarity score) alongside `role_family_plan`.
- **Stage 2 in the UI:** expandable panels for O\*NET occupation matches and role family plan between aptitude profile and verified matches; **Save as PDF** on both panels with page-aware export.

### Data (O\*NET corpus)

- **Load pipeline:** `data/load-onet-postgres.sh` loads O\*NET 30.3 into Postgres via `[onet]` in `config.toml`, creates `occupation_embeddings`, and runs the Hugging Face embed step.
- **Embed tooling:** moved under `data/embed/` (`build_occupation_embeddings.py`, `occupation_profile_from_onet.sql`, table DDL scripts).
- **Connection helpers:** `data/onet-conninfo.sh` and `OnetConfig.conninfo()` for remote-aware libpq connections across data and backend scripts.
- **Verification:** `data/smoke_onet_postgres.py` checks load counts and embedding coverage; optional pytest smoke (`ONET_SMOKE_TEST=1`).
- **Repo hygiene:** O\*NET SQL dumps are **not** tracked in git (`data/download/*` gitignored); `data/README.md` and `data/docs/` document download, INSERT counts, embed tables, and faster reload.

### Backend (API `0.3.0`)

- **O\*NET matching module:** `app/onet/match.py` — embed aptitude profile (`[embedding]`), query `occupation_embeddings` with pgvector, apply `[onet_matching]` (`enabled`, `top_k`, `min_similarity`).
- **Stage 2 orchestration:** `role_family_plan.py` runs vector search before the role-family chat call; progress events include top O\*NET match title.
- **Pipeline response:** `occupation_matches` added to `POST /v1/pipeline` and `POST /v1/stages/2`.
- **Config:** `[onet]`, `[onet_matching]`, and `[embedding]` required in `config.toml`; examples in `config.example.toml` / `config.test.toml`.
- **Dependencies:** `pgvector` / `psycopg` for occupation search at runtime.
- **URL filters:** `skip_domain_suffixes` in `url-filters.toml` blocks subdomains (e.g. `ca.linkedin.com`) via `url_utils.py`.
- **Tests:** `test_onet_match.py`, `test_onet_smoke.py`; updated pipeline, embedding, and URL filter tests.

### Frontend (Web `0.3.0`)

- **New components:** `OccupationMatchesDisplay`, `RoleFamilyPlanDisplay`.
- **Pipeline types:** `occupation_matches` and required `role_family_plan` in `PipelineResult`.
- **PDF export:** `exportOccupationMatchesPdf.ts`, `exportRoleFamilyPlanPdf.ts` (card/page packing consistent with verified matches export).
- **Tests:** component tests for Stage 2 panels; hook/API fixtures updated for full pipeline shape.
- **Version bump** to 0.3.0.

### CI & documentation

- **GitHub Actions:** `backend-tests.yml`, `frontend-tests.yml` (Vitest + build).
- **Docs:** `docs/TESTING.md`, backend/frontend READMEs, and v0.3.0 design notes updated for implemented matching (replacing “planned only” language where applicable).

### Known limitations (acceptable for this release)

- O\*NET tail matches (ranks 3+) can include embedding noise; Stage 2 LLM may still add stretch role families.
- Job discovery may return aggregator/listing URLs (LinkedIn subdomains now filtered; Glassdoor and similar listing pages remain).
- Industry and minimum-salary constraints still not applied in discovery filtering.
