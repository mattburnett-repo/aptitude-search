# 0.9.0 — 2026-08-20

Replace Stage 3 web discovery’s Tavily search with [Exa](https://exa.ai), then harden discovery against stale/junk SERP noise and role skew that semantic search surfaces. Same `search_job_postings` → aptitude fit → synthesis path.

### Frontend

- No changes.

### Backend

- **Exa discovery** — `app/job_discovery/tools.py` calls Exa via `listing_gate.run_exa_search` (`type` from config, default `auto`; `contents.highlights` → snippets). Removed Tavily (`tavily_api_key`, `search_depth`, `search_min_score`).
- **Listing gate** — `app/job_discovery/listing_gate.py` is the single rejection authority: Exa kwargs (`exclude_domains`, optional `include_domains`, date cutoffs, one Exa-valid `exclude_text` phrase) plus post-SERP accept/filter (junk URL/title, closed phrases, parking/error/challenge markers, optional HTTP liveness probe with Exa `get_contents` fallback on challenge pages). Criteria lists live in `url-filters.toml`.
- **Config** — `job_discovery.exa_api_key` (required); `search_type`; `search_max_age_days`; `url_liveness_check` / `url_liveness_timeout_seconds`; existing `discovery_query_max` / `result_top_k` / `url_filters_file`.
- **Deps** — `exa-py` + `httpx` for discovery/liveness; removed `tavily-python`.
- **Role skew mitigations** — Stage 2 prompt O\*NET high/medium/low bands; discovery weights/defers families and terms vs low O\*NET matches; aptitude fit requires search-term / adjacent-role alignment (soft signals downweighted).
- **Stage 2 / pipeline** — `occupation_matches` threaded into Stage 3 discovery where needed for weighting.

### Tests

- `test_search_job_postings.py` — mocks Exa / gate; domain filters and highlight→snippet mapping.
- `test_listing_gate.py` — liveness, closed/parking/error/challenge paths, Exa `exclude_text` constraints.
- Updates to URL filter, URL utils, aptitude fit, and query planner tests.
